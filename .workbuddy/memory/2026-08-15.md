## 识别报错 `whisper-ctranslate2 output file not generated` 诊断 + 修复（commit 982e9fc）
- **现象**：`faster-whisper/large-v3/int8/en` 跑 84s 静默（无 `-->` 进度）后报"output file not generated"，识别失败。
- **语义**：该错是代码在 CLI **退出码 0** 但未生成 `{stem}.json` 时抛的自定义错——说明 whisper-ctranslate2 进程"成功"退出却没写文件（不是下载失败、也不是代理问题）。
- **真 bug**：原代码抛该错时没把 CLI 的 `stderr` 挂到 Error 上，导致真实失败原因被吞（违背"错误信息透传"原则）。同期 JS `transcribeLocal`、Python `whisper` CLI 路径同款缺陷。
- **修复（双端对称）**：`transcribeFasterWhisper`(JS 1759) / `transcribeLocal`(JS 1683) / Python `whisper` CLI(1699) 三处 `throw` 均 `Object.assign(err,{stderr})`，让 catch 块把 CLI 真实 stderr 打印出来。全局副本（LF）已同步，`node --check`/`py_compile` 通过。
- **最可能的根因（待用户用修复后重跑确认）**：用户刚切到 faster-whisper+large-v3，**首次运行需从 HuggingFace 下载 CTranslate2 格式 large-v3（~3GB）**；国内 HF 常被墙/超时，下载中断或模型缓存损坏 → 进程静默退出 0 不写文件。84s 静默即下载/加载阶段。验证法：手动跑 `whisper-ctranslate2 "<音频>" --model large-v3 --device cpu --compute_type int8 --language en --output_dir "<dir>" --output_format json` 看真实 stderr；或查 `~/.cache/whisper`(WHISPER_MODEL_DIR) 下 large-v3 是否完整。
- **提交推送**：`982e9fc` 已推 Gitee + GitHub 双远程（均校验通过）。

## faster-whisper 子进程 Windows gbk 崩溃 + 识别失败显示裸 null（commit b4fd75d）
- **用户现象**：faster-whisper 批量识别，[1051] 报 `UnicodeEncodeError: 'gbk' codec can't encode character '\xb5'`；[1033] 报 `识别失败: null`（看不到原因）。
- **根因**：JS 后端 `transcribeFasterWhisper` 通过 `spawnWithTimeout('whisper-ctranslate2', ...)` 拉起子进程，但没给子进程设 `PYTHONUTF8/PYTHONIOENCODING`。Windows 下 Python 子进程 stdout 默认 gbk，`whisper_ctranslate2/transcribe.py:212 print(make_safe(line))` 打印中文路径/字幕时直接抛 UnicodeEncodeError 挂掉 → 未生成输出文件；不同崩溃阶段把真实 stderr 吞掉 → 错误透传拿到空值显示成裸 `null`。
- **修复（双端）**：
  - `spawnWithTimeout` 统一注入 `env={...process.env, PYTHONUTF8:'1', PYTHONIOENCODING:'utf-8', ...options.env}`（既修 stdout 编码，也修中文路径 argv 解码）；close 时把 stdout 也并入 `stderr` 预览（个别崩溃 traceback 落到 stdout）；错误对象带 `code/stderr/stdout`。
  - `transcribeFasterWhisper` catch：优先 `e.stdout||e.stderr||e.message`，全空时给兜底文案（含退出码）；`retryCall` 成功但返回空文本 → 明确报错「返回空文本或未生成输出文件」。
  - 派发日志 `识别失败: ${result.error}` 加 `_errMsg` 兜底，避免裸 null。
  - Py 端 `local` 后端 `whisper` CLI spawn env 补 `PYTHONUTF8='1'`（与 JS 对称）；派发日志 `None` 兜底。
  - Py 端 faster-whisper 走 `faster_whisper.WhisperModel` 进程内 API（非 CLI），本无 gbk 子进程问题，故无需改该路径。
  - 全局安装副本（LF）已同步，`node --check`/`py_compile` 通过。
- **提交推送**：`b4fd75d` 已推 Gitee + GitHub 双远程（均校验通过）。
