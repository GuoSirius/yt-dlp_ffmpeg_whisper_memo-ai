## YOUTUBE_EXTRA_ARGS 透传 + 下载诊断修复
- 新增 `YOUTUBE_EXTRA_ARGS` 环境变量：透传任意 yt-dlp 参数（JS 用 `parseArgString` 引号感知 tokenizer，Py 用 `shlex.split`），留空则不注入。双端对称（process_videos.js / .py）。用途：缓解 YouTube `web` 客户端限速断流（报错 `1008 bytes read, ... Giving up after 10 retries`，即 yt-dlp 默认 `--fragment-retries 10` 耗尽）。推荐值 `--extractor-args "youtube:player_client=android_vr,web_safari,tv,ios,web"`。文档已补 `.env.example` + `README.md` 环境变量表。
- 下载失败根因：YouTube 对 `web` 播放客户端限速，非流水线 bug；流水线外层 `retryCall` 重跑仍命中同一限速点，故无效。手动救单：用 player_client 切换命令下载到 `output/downloads/<sheet>/task_2058.mp4` 后 `--step transcode,transcribe,analyze,ocr` 复用。
- `--id` 指定行为修复：指定 `--id` 时，仅部分 sheet 含该 id 属正常；原代码每 sheet 未命中都打 `logError` 噪声。改为：未命中 sheet 降级为 `logInfo`（跳过），仅当**所有 sheet 均未命中**才打 `logError`。双端对称修改。
- `sync_global_copy.mjs` 改进 + `.gitignore` 加 `*.bak`：内容一致时跳过备份/写回，避免无谓生成 `.bak`；`.bak` 永不提交。

## sync_global_copy.mjs 移出版本库
- 该脚本硬编码 `D:/Programs/node_npm/...` 全局安装路径 + WorkBuddy 托管 node 路径，属本机专属同步工具，不可移植，用户决定不进版本库。
- 处理：`git rm --cached sync_global_copy.mjs`（保留磁盘文件，本地仍能跑）+ `.gitignore` 新增 `sync_global_copy.mjs`；提交 `0994401` 已 push 到 gitee main。
- ⚠️ git 流程坑：把文件移入 gitignore 时，切勿把它再列进 `git add <file>`——对显式指定的**已被忽略**的文件，`git add` 返回非 0，会截断 `&&` 提交链导致 commit 未真正落库（HEAD 不变、改动仍停在暂存区）。正确做法：仅 `git add` 其余改动文件，已 `git rm --cached` 的删除会自动留在暂存区。
