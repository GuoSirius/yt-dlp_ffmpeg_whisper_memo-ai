## 2026-06-20：修复 --id 匹配失败和 --file 路径解析问题

### 问题
- 用户执行 `video-pipeline --file .\website.xlsx --sheet "普诺赛中文站" --id 343,473,350,365` 报错 `no match for id/title`
- 根因 1：`--file` 相对路径用 `path.resolve(opts.file)` 解析，依赖于 shell cwd，而非项目目录
- 根因 2：`--id` 匹配只认 `COL_ID`（默认 `extra.id`）和 `COL_TITLE`（默认 `title`），Excel 列名不同时匹配失败，且报错信息没有提示可用列名

### 修复
- `--file` 相对路径改为基于 `BASE_DIR`（项目目录）解析，不再依赖 shell cwd
- `--id` 匹配增加 `id`/`ID`/`Id` 候选列名，不再只认 `COL_ID`
- 匹配失败时打印可用列名和 ID 候选列，方便用户确认 `.env` 中 `COL_ID` 是否和 Excel 列名一致
- 移除 `--id` 匹配中不必要的 `try-catch`（`Math.floor(Number(x))` 不会抛异常）

### 提交
- `fix: --id 匹配失败无提示、--file 路径解析相对于 cwd 而非项目目录`

## 2026-06-20 上午：--id 兼容 PowerShell 逗号为空格的展开问题

### 问题根因
- PowerShell 中 `343,473,350,365` 是数组字面量，传给外部命令时会被展开成空格分隔
- 导致 `opts.id = ['343 473 350 365']`（单个字符串元素，含空格）
- 之前只按逗号 split，匹配不到任何行

### 修复（JS + Python 均改）
- JS `run()` 入口：兜底 `targetIds.join(',').split(/[,，\s]+/)`
- JS reducer：同时支持逗号、中文逗号、空白字符分隔
- Python `target_ids` 解析：`re.split(r'[,，\s]+', str(v))` 替代固定 `str(v).split(",")`

### 提交
- `fix: --id 兼容 PowerShell 逗号为空格的展开问题（js/python 均修）`
