## 修复 AI 分析 prompt `$` 替换 bug + 添加 AI_DEBUG 日志

### 问题：命令行跑的 AI 分析结果（关键词）与千问桌面不一致
- **根因（JS）**：`promptTpl.replace('{content}', text)` 中 `text` 含 `$&` `$\`` `$'` `$$` 时，
  JS `String.replace` 会特殊解释这些模式，导致发给 AI 的转录文本被损坏。
  例如 `$&` 被替换为匹配的 `{content}`，`$\`` 被替换为匹配前的文本。
  Python `str.replace` 无此问题。
- **修复（JS）**：改用函数替换 `promptTpl.replace('{content}', () => text)`，规避 `$` 特殊语义。
- **新增 AI_DEBUG**：`.env` 设 `AI_DEBUG=true` 时，打印实际发送的 prompt 前 500 字符 + AI 返回内容前 500 字符，
  方便排查"关键词质量不对"类问题。JS + Python 均已添加。
- 位置：JS `stepAnalyze` line 1051；Python `step_analyze` line 1037

## 修复 funasr 检测 + dry-run 输出信息不匹配问题

### 问题1：dry-run 环境检测显示 `whisper (service http://localhost:9588)` 而非 `funasr/cli`
- **根因**：`printDryRun` 函数（line 3024）的 `backend` 变量只判断了 `local` 和 `service` 两种，
  `faster-whisper` 和 `funasr` 均走 else 分支，被错误显示为 `service ${WHISPER_SERVICE}`。
- **修复**：与 `checkEnvironmentAsync` 保持一致，补充四分支判断：
  `local` / `faster-whisper (whisper-ctranslate2)` / `funasr/${FUNASR_MODE}` / `service ${WHISPER_SERVICE}`

### 问题2：funasr CLI 检测报错"不可用"，实际命令行可用
- **根因1**：原来用 `funasr --help` 做检测，但 funasr 启动时会触发 Hydra 框架初始化，实测耗时 ~20 秒，
  超过 execSync timeout: 5000ms → SIGTERM → 被误判为不可用。
- **根因2（尝试方案）**：换用 `python -c "import funasr"` 同样耗时 ~21 秒（funasr 导入时大量初始化），仍不适用。
- **最终修复**：改用 `where funasr`（Windows）/ `which funasr`（Linux/macOS）检查可执行文件是否存在，
  纯磁盘查找，< 1 秒，准确可靠。
- **注**：`FUNASR_PYTHON` 环境变量保留（原来为 python import 方式引入），现在实际已不使用，可后续清理。
