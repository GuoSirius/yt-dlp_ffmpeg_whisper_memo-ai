## 任务11: 修复 dotenv \n 转义不解析 → AI prompt 格式错乱 (23:25)

### 问题
用户更新了 .env 中的 AI_PROMPT_TPL（两步法模板）和 INITIAL_PROMPT 后重新运行，但 AI 分析结果与之前完全一样，语义修正无效。

### 根因
dotenv v17 在无引号值中不解析 `\n` 转义。`.env` 中 `AI_PROMPT_TPL=...关键词。\n\n【第一步...` 被读为字面量 `\n`（反斜杠+n），而非真正换行符。LLM 收到的 prompt 是一整行无格式的字符串，无法正确解析两步法结构。

验证: `node -e` 读取实际 .env 文件 → `JSON.stringify` 输出含 `\\n` → 确认字面量。

更荒谬的是: 不配置 `.env` 反而更好——因为硬编码 fallback 用的是 JS 模板字面量 `\n`（真换行）。

### 修复
JS + Python 在读取 `AI_PROMPT_TPL` 后统一执行 `replace(/\\n/g, '\n').replace(/\\t/g, '\t')`。
- `process_videos.js` L769: `rawPromptTpl.replace(...)` 
- `process_videos.py` L795: `prompt_tpl.replace("\\n", "\n")`

同步全局 video-pipeline 副本。

## 任务7: 修复 AI 分析失败时错误信息为 null 的 Bug

### 根因分析（3 个问题叠加）
1. **retryCall 返回值嵌套结构不匹配**：retryCall 返回 `{result, retriesUsed, error}`，但 stepAnalyze 按 `{text, retries, error}` 解构 → `result.text` 拿到的是嵌套对象（永远 truthy），`result.error` 来自 retryCall 顶层（永远是 null）
2. **isRetryable 对 API HTTP 5xx 错误不重试**：fetch 抛出的 HTTP 错误无 `.stderr`、无 `.code` → `return false` → 一次失败直接退出
3. **Python 版重试时复用同一 request 对象**：urllib Request 的 data 流可能被消费后无法再读

### 修复内容
- **JS stepAnalyze** (process_videos.js L768-810): 正确解包 retryCall 返回 → `ret.result` 取 fnResult → `fnResult.text` 取实际文本；空内容设置明确错误信息
- **JS isRetryable** (process_videos.js L569-586): 新增 HTTP 5xx 错误匹配 `err.message?.match(/^HTTP\s+5\d{2}/)` → 可重试
- **Python step_analyze** (process_videos.py L774-806): 每次重试重建 urllib Request 对象；status != 200 时捕获响应体；安全访问 `body.get("choices")`
- 两版语法检查均通过
