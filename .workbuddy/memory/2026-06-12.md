## 任务1: 排查语音识别质量问题（错字/漏字/繁体）

### 根因分析
1. `/inference` 缺少 `language=zh` → 繁体字混入 + 错字（用户自行在服务后台设定）
2. medium 模型精度不足（中文 WER ~12%）→ 错字/漏字
3. ffmpeg 转码参数简陋：
   - `-ac 1` 简单混音存在相位抵消风险
   - 未指定 resampler（默认 swr）
   - 无响度归一化
   - 无抖动处理（24/32→16bit 截断失真）

→ 用户决定：language 自己设定、转码参数优化、模型自己选

## 任务2: 优化 ffmpeg 转码参数

### 新 TRANSCODE_ARGS
```
-vn -map_metadata -1 -map 0:a:0 -af loudnorm=I=-16:TP=-1.5:LRA=11:linear=true,aresample=resampler=soxr:osr=16000:osf=s16:dither_method=shibata -ac 1 -c:a pcm_s16le
```

### 改动文件
- process_videos.js: 更新默认 TRANSCODE_ARGS
- process_videos.py: 更新默认 TRANSCODE_ARGS
- .env.example: 替换旧 TRANSCODE_ARGS 段，逐项详解
- .env: 同步更新（未提交，gitignored）

### 各参数作用
| 参数 | 作用 |
|---|---|
| -vn | 跳过视频流，加速 |
| -map_metadata -1 | 剥离元数据 |
| -map 0:a:0 | 只取第一音频流 |
| loudnorm | EBU R128 响度归一化到 -16 LUFS |
| aresample=soxr | 高质量重采样器（比 swr 精度更高） |
| dither_method=shibata | 芝畑抖动消除量化失真 |
| -ac 1 | 单声道 |
| -c:a pcm_s16le | WAV PCM 16-bit |

### 验证
- 合成音频测试 OK
- 真实视频转码 OK（pcm_s16le, s16, 16000Hz, 1ch, 376.2s）
- JS/Python 语法检查通过
