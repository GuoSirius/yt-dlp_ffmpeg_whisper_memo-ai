## CHANGELOG 重复问题根因修复 (2026-06-11 12:23~12:30)

### 问题
用户反馈 v1.0.3 的 CHANGELOG 条目再次包含了全部历史提交（不仅是该版本的变更）。

### 根因
`getLastTag()` 函数用了 `head -1`：
```js
return runSilent('git tag --sort=-v:refname --merged HEAD | head -1');
```
Windows 上 `execSync` 使用 `cmd.exe`，而 `cmd.exe` 没有 `head` 命令。管道失败后 `runSilent` 静默 catch 返回空字符串 `''`。
于是 `generateChangelogEntry()` 中 `getLastTag()` 返回空，`range` 退化为 `'HEAD'`（全量提交），导致每个版本都记录了全部历史。

### 修复 (`755222a`)

**修复 1: getLastTag() 改用纯 JS 取第一行**
```js
function getLastTag() {
  const tags = runSilent('git tag --sort=-v:refname --merged HEAD');
  if (!tags) return '';
  return tags.split('\n').filter(Boolean)[0] || '';
}
```
不再依赖 `head` 命令，避免 Windows `cmd.exe` 兼容性问题。

**修复 2: updateChangelog() 正则兼容条目在开头**
```js
// 旧：要求 \n##  开头（条目在文件第一条时匹配失败）
const re = /\\n## 1\.0\.3 — .*?(?=$|\n## )/s;

// 新：允许条目作为文件开头
const re = /(^|\n)## 1\.0\.3 — .*?(?=$|\n## )/s;
```

## sed 模式修复：兼容不同标题层级 (15:42)

### 问题
用户指出 `sed -n "/^## \[$VERSION\]/"` 硬编码了 `##`，但 `standard-version`/`conventional-changelog` 在不同 semver bump（major/minor/patch）下可能产生不同 `#` 数量的标题（`##` vs `###`），导致 major 版本提取失败。

### 修复
```bash
# 旧：硬编码 ##
sed -n "/^## \[${VERSION}\]/,/^## \[/p"

# 新：匹配任意标题层级
sed -nE "/^#+ \[${VERSION}\]/,/^#+ \[/p"
```

- `#+` 在 `sed -E` 模式下匹配一个或多个 `#`，兼容 `##` / `###` / `####` …
- `^#+ \[` 不会误匹配 `### Bug Fixes`（因为 `Bug Fixes` 不以 `[` 开头）
- 测试通过：`## [1.2.3]`（当前格式）和 `## [2.0.0]`（模拟 major 格式）

**提交**: `86f2e5b` fix(ci): sed 模式改用 #+ 匹配任意层级标题

```js
// 短键 bilibili → prefix=BILIBILI → 查找 BILIBILI_URL_TPL ✅

```

```js
const _PKEY_ENV_PREFIX = {
```
