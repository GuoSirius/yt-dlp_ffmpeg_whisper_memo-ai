## CHANGELOG 重复问题根因修复 (2026-06-11 12:23~12:30)

### 问题
用户反馈 v1.0.3 的 CHANGELOG 条目再次包含了全部历史提交（不仅是该版本的变更）。

### 根因
`getLastTag()` 函数用了 `head -1`：
```js
return runSilent('git tag --sort=-v:refname --merged HEAD | head -1');
```
Windows 上 `execSync` 使用 `cmd.exe`，而 `cmd.exe` 没有 `head` 命令。管道失败后 `runSilent` 静默 catch 返回空字符串 `''`。
于是 `generateChangelogEntry()` 中 `getLastTag()` 返回空，`range` 退化为 `'HEAD'`（全量提交），导致每个版本都记录了全部历史。

### 修复 (`755222a`)

**修复 1: getLastTag() 改用纯 JS 取第一行**
```js
function getLastTag() {
  const tags = runSilent('git tag --sort=-v:refname --merged HEAD');
  if (!tags) return '';
  return tags.split('\n').filter(Boolean)[0] || '';
}
```
不再依赖 `head` 命令，避免 Windows `cmd.exe` 兼容性问题。

**修复 2: updateChangelog() 正则兼容条目在开头**
```js
// 旧：要求 \n##  开头（条目在文件第一条时匹配失败）
const re = /\\n## 1\.0\.3 — .*?(?=$|\n## )/s;

// 新：允许条目作为文件开头
const re = /(^|\n)## 1\.0\.3 — .*?(?=$|\n## )/s;
```

**修复 3: 完整重建 CHANGELOG.md**

**修复 4: 新增 scripts/regenerate-changelog.js**

## 改进发布流程：未提交文件提示 + 移除 GITHUB_TOKEN (15:03 - 15:12)

### 问题
1. `npm run release` 检测到未提交文件时只打印警告，不提示提交
2. `release-it` 的 `github.release: true` 需要 `GITHUB_TOKEN`，用户不想提供

### 改动

**scripts/release.js**
- 未提交文件 → 列出变更 → `confirm` 询问是否提交
- 确认 → `input` 输入 commit message（默认 "chore: update before release"）
- 执行 `git add -A && git commit -m "..."` 后重新检查，仍有未提交文件则报错退出
- dry-run 模式跳过提交提示

**.release-it.json**
- `github.release: false` — GitHub Actions (softprops/action-gh-release@v2) 自动创建 Release
- 移除 `tokenRef` / `releaseName` / `autoGenerate` 等冗余配置

**.env.example**
- 移除 `GITHUB_TOKEN` 配置段

**package.json**
- 移除 `release:it*` 5 个 npm scripts
- 卸载 `dotenv-cli`
