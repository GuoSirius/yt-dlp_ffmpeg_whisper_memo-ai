# 2026-06-11 工作日志

## 全面测试 process_videos.js 并修复 2 个 Bug

### Bug #1（关键）: `--force` 不重新下载已有文件
- **现象**: `node process_videos.js --sheet "普诺赛中文站" --limit 5 --offset 8 --force --step download` 不重新下载
- **根因**: `stepDownload` 中 force=true 时跳过了脚本层的文件检查，但未给 yt-dlp 传递 `--force-overwrites`，导致 yt-dlp 静默跳过已有文件
- **修复**: 在 `stepDownload` 中 force=true 时添加 `args.push('--force-overwrites')`
- **验证**: 249.mp4 时间戳从 `21:54:28` → `22:15:45`（真实重新下载），252.mp4 从 `22:12:44` → `22:13:32`

### Bug #2（次要）: Commander parseInt 回调产生 NaN
- **现象**: `--concurrency 3` 显示 `concurrency: NaN`
- **根因**: Commander 的 coerce 回调签名为 `(value, previous)`，当默认值非 0 时（如 concurrency 默认 1），`parseInt('3', 1)` 因 radix=1 无效返回 NaN
- **修复**: 所有 parseInt/parseFloat 回调改为箭头函数显式传参：`v => parseInt(v, 10)`
- **影响范围**: --concurrency, --retry, --download-timeout, --transcode-timeout, --transcribe-timeout, --analyze-timeout, --retry-delay

## Python 版 process_videos.py Bug 修复

### Bug #1（关键）: `--force` 不重新下载 → 同 JS 版，已修复
- **根因**: `step_download()` 中 force=True 时跳过了 Python 层的文件检查，但 yt-dlp 命令未加 `--force-overwrites`
- **修复**: 在 `step_download()` 构建 cmd 时，force=True 追加 `cmd += ["--force-overwrites"]`
- **验证**: 252.mp4 时间戳从 `2026-06-10 16:33:55` → `2026-06-11 22:21:58`，完整进度条真下载

### Bug #2（parseInt NaN）: Python 不受影响
- Python argparse 使用 `type=int` 而非回调，不涉及 Commander.js 的回调签名问题

### 发现额外问题: Python 脚本在 Windows GBK 环境下 Unicode 输出报错
- 设置 `PYTHONIOENCODING=utf-8` 可临时规避（脚本本身已在 `run_with_progress` 中设置 `PYTHONIOENCODING=utf-8`，但主进程输出未设）
