# 2026-06-11 工作日志

## 任务1: JS版 Bug 修复（--force 不重新下载）

### Bug #1（关键）: `--force` 不给 yt-dlp 传 `--force-overwrites`
- **现象**: 已下载的文件，加了 --force 也不重新下载，只输出 "download done" 但 yt-dlp 静默跳过
- **根因**: stepDownload 在 force=true 时跳过了脚本层的文件检查，但 yt-dlp 默认不覆盖已有文件
- **修复**: 在 stepDownload() 中 force=true 时给 yt-dlp 追加 `--force-overwrites`
- **验证**: 249.mp4(21:54→22:15) 和 252.mp4(22:12→22:13) 两个文件时间戳均更新，有真实下载进度

### Bug #2（次要）: `--concurrency` 等数值参数解析为 NaN
- **根因**: Commander v15 的回调签名 `(value, previous)`，parseInt 作为回调时默认值被当作 radix → NaN
- **修复**: 所有 parseInt/parseFloat 回调改为 `v => parseInt(v, 10)` / `v => parseFloat(v)`
- 残留 `.part` 文件清理 ✅

## 任务4: 修复 report 文件名双点 (..json) 问题

### 问题
- 用户报告文件名出现 `report_20260611_142445..json`（连续两个点）
- 仅 JavaScript 版本受影响

### 根因
- `generateReport()` 第1287行使用 `toISOString().split('.')[0].replace(/[-:T]/g, '').replace(/(\d{8})(\d{6})/, '$1_$2')` 链式处理生成时间戳
- 虽然正常情况不会产生 `..`，但链式依赖 `toISOString` 的格式假设不够健壮

### 修复
- 改为显式日期组件拼接：`getFullYear() + padStart(month+1) + padStart(date) + '_' + padStart(hours) + padStart(minutes) + padStart(seconds)`
- 彻底消除对 `toISOString` 格式的依赖，100% 可靠

### Python 版
- `datetime.now().strftime("%Y%m%d_%H%M%S")` 不受影响，无需修改

## 任务5: 增强下载/转码/识别/AI分析进度日志

### 需求
- 音视频分开下载时，明确标注当前下载的是视频流还是音频流
- 下载完成输出文件名、大小、耗时
- 转码完成输出文件名、大小、耗时
- 识别/AI分析完成输出耗时和内容长度

### 实现（process_videos.js）

#### 新增辅助函数
- `parseYtdlpStage(line, state)` - 解析 yt-dlp 输出的阶段信息
  - 匹配 `[download] Destination:` 行，通过计数器区分视频/音频
  - 匹配 `[download] 100%` 行，输出完成信息（含阶段标签）
  - 匹配 `[Merger]` 行，标记合并阶段
  - 返回 bool：是否应该跳过后续进度解析
- `fmtElapsed(ms)` - 格式化毫秒为可读耗时（秒/分钟）

#### 下载阶段检测（dlState 模式）
- `dlState = { destCount: 0, currentDest: null, currentPhase: null }`
- yt-dlp bestvideo+bestaudio 总是先下载视频再下载音频，顺序固定
- destCount === 1 → video 阶段，destCount === 2 → audio 阶段
- 匹配 `[download] Destination:` 获取目标文件名
- 匹配 `[download] 100% of ~N.MiB` 获取下载大小

#### 下载完成日志
- 添加 downloadStart 计时器
- 输出: `✔ [id] 下载完成 -> filename (N.MB, Xs)`

#### 转码完成日志
- 添加 transcodeStart 计时器
- 输出: `✔ [id] 转码完成 -> filename (N.MB, Xs)`

#### 识别/AI分析完成日志
- 添加 aiStart 计时器（3个调用点：processOneTask, runInputTask, runContentTask）
- 识别: `✔ [id] 识别完成 (Xs, N 字符)`
- AI分析: `[id] AI analysis done (Xs, N chars)`

#### 正则修复
- 100% 匹配: `/\[download\]\s+100% of/` → `/\[download\]\s+[\d.]+%\s+of/`（适配 100.0%）
- 目标文件匹配: 支持 `.f248.mp4` 和 `.m4a` 两种格式
