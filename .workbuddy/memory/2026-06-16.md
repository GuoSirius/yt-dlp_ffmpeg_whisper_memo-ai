## 断点续跑（resume）机制分析

### 用户问题
1. 中途中断，已执行的数据是否写入 Excel？
2. 下次重跑是从头、从第 7 条、还是从第 7 条未完成环节继续？
3. 期望：成功的跳过、部分成功的从断点继续、最终所有结果都进 Excel

### 现状（重要：与用户预期差距大）
**Python (`process_videos.py`) 和 JS (`process_videos.js`) 行为一致：**

1. **进度文件**：每条任务完成后立即写 `output/progress/{sheet}/task_{stem}.json`
   - `save_task_progress()` / `saveTaskProgress()`
   - 仅记录最终结果，不被 `process_one_task()` 读回
2. **Excel 写回**：仅在所有任务都跑完后批量写一次
   - `write_all_contents_to_excel()` / `writeAllContentsToExcel()` 在 `run()` 末尾调用
   - **中断时这一行不执行，Excel 里前 6 条不会写回任何内容/keywords**
3. **跳过逻辑**：只在每个 step 内部根据"文件是否存在"判断
   - `step_download` (line 1007-1009): `if not force: ...` 检查目标文件
   - `step_transcode` (line 1089): `if not force and out_file.exists() and out_file.stat().st_size > 0: return skip`
   - `step_transcribe` 跳过判断在 `process_one_task` 里读 `tc_path.exists()`
   - `step_analyze` 同理
   - **这些都是单 step 内的局部检查，不是基于 progress JSON 的全局 checkpoint**
4. **没有 step 级 checkpoint 重启机制**
   - 第 7 条 download 成功、transcode 失败 → 下次重启会从 download 重新开始
   - 因为 transcode 失败时 `result.transcode = StepResult("failed")`，下次不会跳过 download（文件存在），但会重做 transcode ✓
   - 真正的问题：如果第 7 条 download 成功、transcode 成功、transcribe 中途异常，transcode 文件存在 → 下次跳过 transcode ✓
   - 但 download/transcode 文件被删除或损坏 → 无法恢复，会重头跑
5. **`--force` 行为**：强制覆盖所有已有文件
6. **`--retry-failed <report.json>`**：基于上次 report JSON 重跑 `overall_status in (failed, partial)` 的任务
   - 缺点：必须等上次完整跑完并生成 report

## 错误信息不透传修复

### 用户反馈
faster-whisper 转码失败时，日志只显示 "识别失败: Exit code 2"，
stderr 内容（含真实错误原因）完全没有被输出，导致无法排查。

### 根因
- JS `spawnWithTimeout` 在子进程非 0 退出时，`reject` 的 error.message
  只有 "Exit code 2"，stderr 被挂在 `e.stderr` 属性上但所有调用方
  只读了 `e.message`，`e.stderr` 被丢弃
- Python `_transcribe_local` 的 stderr 被逐行消费做进度条，
  失败时没有把 stderr 内容带出来
- Python `_transcribe_faster_whisper` except 块只打了 `str(e)[:500]`，
  且缺少上下文（音频路径、模型配置等）
- 汇总打印和逐任务打印处用 `[:120]` / `[:200]` 硬编码截断

### 改动
- **`spawnWithTimeout` (JS)**：reject 时把 stderr 末尾（最长 3000 字符）
  直接写进 `error.message`，所有调用方自动受益
- **Python `_transcribe_local`**：`_run()` 内积累 stderr 每行，
  `proc.returncode != 0` 时随 `RuntimeError` 一并抛出
- **Python `_transcribe_faster_whisper` except 块**：
  - 打印音频路径、模型配置、完整 `traceback`
  - 检测 SSL/CERTIFICATE 相关错误时给出解决提示
    （设置 `SSL_CERT_FILE` / `pip install --upgrade certifi` /
    预下载模型到本地目录并设 `WHISPER_MODEL_DIR`）
- **JS 三个 transcribe catch 块**：`e.stderr || e.message` 优先取 stderr，
  上限提至 5000 字符
- **Python `_print_long()` / JS `printLong()` 辅助函数**：
  错误信息超长时截断并提示，含换行时逐行缩进打印
- **汇总打印 & 逐任务打印**：改用 `_print_long` / `printLong`，
  不再 hard-code `[:120]` / `[:200]` 截断
